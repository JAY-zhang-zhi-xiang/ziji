# 自记：个人自动记账

这是一个只给个人使用的轻量自动记账软件，参考“AI 自动记账”的体验。Android App 在用户主动授权通知读取权限后，可以识别微信、支付宝、云闪付和银行卡消费通知，并把账单直接保存在手机本地；电脑服务只用于可选的网页查看、备份和导入，不需要一直开机。

## 现在能做什么

- **两条自动采集通道**：通知监听 + 页面识别（无障碍服务），互为补充。
- **覆盖的 App**：微信、支付宝、云闪付、12 家银行（工/建/农/中/交/招/浦发/中信/广发/平安/邮储/兴业），以及淘宝、天猫、京东、京东金融、拼多多、饿了么、抖音、美团/美团外卖/美团买菜——这些电商外卖 App 内支付时（含微信/支付宝 SDK 收银台），页面识别同样能读到成功页。电商 App 只开页面识别通道，不读它们的通知（订单/促销通知是垃圾源）。
- Android 消费通知直接在手机本地自动入账，不依赖电脑在线。
- **页面识别通道**：支付成功后停在支付结果页，App 会自动读取页面上的金额和商户并入账；不依赖支付 App 是否主动发通知。
- 每次打开 App 都会核对通知与页面识别权限，权限被系统（ROM 省电策略）静默关闭时首页状态卡如实显示，并弹窗引导一键跳回系统设置开启。
- 两条通道识别到的同一笔支付会自动去重，不会重复记账。
- 手机主页面显示本月支出、今日支出和最近账单。
- 最近账单使用独立卡片展示，点击可纠正金额、商户、账户、分类、用途、收支方向和日期，或删除误记账。
- 账单可以导出成 Excel 能直接打开的 CSV（带「用途」列），也能从 CSV 导入回来；手机端和网页端互相能导，重复导同一个文件不会让账本翻倍。
- 自动识别金额、商户、微信/支付宝/银行卡账户和常见消费分类。
- 电脑关机或不配置同步地址时，本地自动记账仍然正常工作。
- Android 伴侣自动读取微信、支付宝、银行卡通知，识别金额、商户、账户、分类和时间。
- 已覆盖常见花呗交易对象、微信支付、银行信用卡/储蓄卡消费、快捷支付 `支出(商户)` 等通知格式。
- 识别到金额后直接入账；无法识别金额时不生成空账单，使用手动记账补录。
- 自定义关键词规则，例如“瑞幸 -> 餐饮”。
- 教一次改一片：手动改过某笔的分类后，同商户历史上还停在「其他」的记录会一起归类，不用一笔笔点。
- 账本支持按关键词、收支方向和分类搜索筛选。
- 按月回看：首页和统计页都能翻到上一个月，支出、日均、分类排行、明细跟着切换；未来的月份不可选。
- 退款自动冲抵：退款按「同商户 + 30 天内 + 金额不超过原支出」匹配回原分类并从支出中扣除，不再计入收入；找不到原交易的单独挂在「退款」项下，保证总支出仍对得上。跨月退款回到原交易所在的月份冲抵，不会让退款当月出现负数支出。
- 交易时间优先取原文里写的时间（`2026-10-17 12:31`、`10月17日 12:31`、`昨天 12:31`、`12:31`），解析不出来才用通知到达时间，跨午夜和跨月的账不会记错日期。
- 支持从“我的”中备份/恢复完整账本，包含账单、规则、账户和自动捕获记录。
- 本月预算、今日支出、分类图、最近账单。
- 导入 `.txt`、`.csv`、`.tsv`、`.json` 文本账单。
- 本地桥接自动捕获：外部通知助手/快捷指令可以 POST 消费文本到 `/api/capture`。
- 自动捕获的账单会显示来源标签，例如 `Android 通知`；自动记录的账单会显示 `自动入账`。
- Android 伴侣会合并通知标题、正文、多行文本和 ticker，尽量捕获完整付款信息。
- Android 伴侣也支持系统“分享文本”入口：从支付详情、短信或聊天里把账单文本分享给“发送到自记”，会进入同一条桥接/待补发链路；如果分享的是桥接地址或 PWA token 链接，则会自动保存桥接配置。
- Android App 会对 2 分钟内的相同通知短时去重；跨通道判重按「金额 + 方向 + 时间」判定；**同一商户、同一金额、10 分钟内的记录一律判为同一笔**——支付结果页会在屏幕上停留并反复触发识别，这条规则保证同一笔支付不会被记成多笔，超过 10 分钟的则视为真实第二笔正常入账。
- 如果启用了可选电脑同步但电脑暂时不可达，会最多暂存 50 条待同步账单，后续连通后补发。
- App 内测试账单与真实通知共用同一个自动记账处理器，可验证过滤、去重、解析、本地保存和同步排队整条链路。
- 手机主页可查看最近支付通知的处理状态，显示已入账、已去重、缺少金额或缺少支付动作，排查时不依赖电脑日志。
- Android 伴侣补发历史账单时会每成功发送 1 条就立刻更新本地队列，降低半路断网导致重复补发的概率。
- 桥接层也会忽略尚未被网页领取的重复通知文本，降低重复账风险。
- 导出 CSV 或 JSON 备份。
- PWA 离线缓存，可添加到手机桌面。

## 怎么运行

### 只在 Android 手机上使用

1. 安装项目根目录生成的 `自记-自动记账.apk`。
2. 打开 App，点击“开启通知读取权限”，在系统设置中允许“自记自动记账”读取通知。
3. 进入“自动记”页，点击“开启页面识别权限”，在系统设置的“已下载的服务”里开启“自记自动记账（页面识别）”。
   - 覆盖安装新版本后，如果页面识别不工作，去系统设置把这个无障碍服务**先关闭再开启**一次（白名单有变动时需要重新绑定才生效）。
4. 建议点击“检查后台运行设置”，按提示允许自启动、把省电策略设为“无限制”，避免被系统冻结。
5. 之后正常消费即可（微信、支付宝、云闪付、银行卡、淘宝/京东/拼多多/饿了么/抖音/美团等）：
   - 有支付通知时，通知通道自动入账；
   - 没有通知时，支付完成后停在支付结果页片刻，页面识别通道会自动入账。

电脑同步地址可以留空；留空时电脑不需要开机。

### 关于两条采集通道

| 通道 | 触发条件 | 需要权限 |
| --- | --- | --- |
| 通知监听 | 支付 App 主动发出系统通知 | 通知读取权限 |
| 页面识别 | 支付成功页出现在前台 | 无障碍服务权限 |

两条通道识别到同一笔支付时，会按「金额 + 方向 + 时间」自动去重（同商户同金额 10 分钟内判同一笔）。页面识别只读取白名单 App（支付渠道、银行、电商外卖平台）的支付页面文字，不截屏、不读取密码，也不上传任何数据；聊天窗口、订单列表/状态页（含「已支付」状态词）一律拒绝，防止把历史消息和订单状态误记成新消费。

### 开发与可选电脑同步

先做一次环境自检：

```powershell
npm.cmd run doctor
```

它会检查 Node.js、Java、Android SDK、`gradlew.bat`、5188 端口和局域网 IPv4 地址，并打印手机浏览器和 Android 通知伴侣可用的访问地址。

如果只是想确认“当前代码、解析器、桥接服务和 Android 端纯 Java 逻辑都没有坏”，运行：

```powershell
npm.cmd run check:ready
```

这个命令会执行完整测试、Node 语法检查、临时启动桥接服务，并用支付宝、微信、银行卡、云闪付样本做一次端到端模拟。它不需要 Android SDK，也不会证明真机通知已经可用；真机自动记账仍然需要后面的 APK 安装和真实通知验证。

在当前目录启动本地服务：

```powershell
npm.cmd start
```

然后打开：

```text
http://127.0.0.1:5188
```

如果要让手机访问同一局域网里的电脑，请用：

```powershell
npm.cmd run start:lan
```

这个命令会自动打印手机浏览器要打开的网页地址，以及 Android 通知伴侣要填写的 `/api/capture` 地址。然后在手机浏览器打开电脑的局域网 IP，例如：

```text
http://192.168.1.23:5188
```

手机打开后，可以用浏览器菜单选择“添加到主屏幕”。

启动局域网服务后，可以单独做一次手机接入前检查：

```powershell
npm.cmd run bridge:preflight -- -Token <token>
```

如果要用真实样本通知文本验证桥接接口解析和待领取队列：

```powershell
npm.cmd run bridge:verify-samples -- -Token <token> -Claim
```

## 自动捕获接口

本地服务启动后，可以把微信、支付宝、银行卡通知文本 POST 到接口：

```powershell
curl.exe -X POST http://127.0.0.1:5188/api/capture `
  -H "Content-Type: application/json" `
  -d "{\"source\":\"test\",\"text\":\"支付宝 06月06日 12:31 向 星巴克 付款 32.00元 付款方式 花呗\"}"
```

如果同一条通知文本在网页领取前被重复 POST，接口会返回 `added: 0` 和 `duplicates: 1`，不会重复进入待处理队列。

`npm.cmd run start:lan` 默认会生成 token，并打印：

- 手机浏览器打开的 PWA 地址。
- Android 通知伴侣填写的 `/api/capture` 地址。
- Android 通知伴侣填写的 token。
- 手机浏览器保存 token 用的 `?bridgeToken=...` 地址。

生成的 token 会写到 `data/bridge-token.txt`，**重启后保持不变**，手机端只需要配置一次。想换 token 就删掉这个文件，或者用环境变量显式指定：

```powershell
$env:ZIJI_TOKEN="你的私密口令"
npm.cmd run start:lan
```

带 token 的接口调用：

```powershell
curl.exe -X POST http://电脑局域网IP:5188/api/capture `
  -H "Content-Type: application/json" `
  -H "X-Ziji-Token: 你的私密口令" `
  -d "{\"source\":\"android-notification\",\"text\":\"微信支付收款助手：你已向 美团外卖 支付 ¥46.80，支付方式 零钱\"}"
```

如果网页提示“自动捕获需要 token”，用下面地址打开一次，应用会把 token 存到本机浏览器：

```text
http://电脑局域网IP:5188/?bridgeToken=你的私密口令
```

只有在完全可信的局域网临时调试时，才建议直接运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-lan.ps1 -NoToken
```

### 数据文件不对外暴露

`data/` 目录（账单缓存 `auto-captures.json`、`bridge-token.txt`、`.bak` 备份、隔离出来的
`.corrupt-*` 文件）不会被网页服务读取，直接访问会返回 404。token 保护的是 `/api/` 接口，
文件路径这一层同样做了拦截——包括大小写不同的 `/Data/...`（Windows / macOS 的
文件系统不区分大小写）。

## 关于“全自动记账”的现实边界

网页/PWA 不能直接读取微信、支付宝或银行卡流水，也不能绕过系统权限读取通知、短信或 App 内数据。这个版本先实现个人可用的“低摩擦自动化”：

- 支付后由 Android 伴侣自动读取通知并在手机本地入账；没有读到通知时直接使用 PWA 的手动记账表单。
- 电脑桥接 `/api/capture` 只用于把手机自动捕获结果同步到 PWA；银行卡如果是短信提醒，也会通过 Android 的通知回调被伴侣捕获。
- 手动记账是通知读取失败或通知格式不完整时的兜底方式。
- 数据全本地保存，不依赖服务器。

### 两端一套配色

网页端一直是米黄纸 + 墨绿 + 楷体的手账风，手机端在 v0.9 就换成了暖灰纸 + 赤陶 + 无衬线。两边各做各的，同一个应用在两块屏幕上像两个产品。

现在网页端的 `:root` 直接取 Android `SettingsActivity` 里的 `COLOR_*`：底色 `#ECE8E0`、卡片 `#FEFDFA`、强调 `#A4432D`、正文 `#2A2E32`、描边 `#DED8CE`、收入绿 `#2F7A5F`。圆角统一成卡片 16 / 按钮 12 / 标签 999，阴影只留一层 `0 2px 14px rgba(15,18,22,.07)`，靠描边和色差分层，不再用胶带、装订线、横线纸这些手作装饰。

改的过程中捞出三个一直存在、但被粗糙配色掩盖的布局问题：

- **首屏顶部永远空 150px**：`<svg class="icon-sprite">` 上的 `hidden` 属性对 SVG 不生效，它按 inline 元素实打实占位。换配色后 hero 变浅，这块空白才暴露出来。
- **分类进度条从来没画出来**：`.chart-bar` 是 `<span>`，默认 `display: inline`，`height: 100%` 和 `width: 45%` 全部无效，只有灰色轨道可见。加 `display: block` 才显示。
- **手机上分类下拉框高 108px**：`.rule-form select { flex: 0 0 108px }` 在竖排（`flex-direction: column`）下，flex-basis 变成了**高度**。输入框同理被拉成 130px。

收入色也从强调色里拆了出来——强调色改成赤陶后，`--money-in` 跟着它走，收入会被涂成红色，收支语义直接反了。

### 用途：从「手动补」变成「自动读」

支付成功页和支付通知里本来就写着用途，只是早期的解析把整页文本压平成一串、标签和值对不上号，于是「商品说明」后面那行商品名被当成噪声丢掉了。v0.9 按可信度分三层读，命中一层就停：

1. **页面字段（最准）**——无障碍服务按视觉阅读顺序保留节点，「商品说明」「订单标题」「交易说明」「转账说明」「备注」后面紧跟的那个值就是用途。例如节点序列 `… 瑞幸咖啡 / 商品说明 / 生椰拿铁 / 支付方式 / 零钱` → 用途「生椰拿铁」。
2. **通知字段**——转账通知里的「转账说明：午饭AA」直接作为用途；支付通知里的「商品说明」同理。
3. **品牌词典**——内置 200+ 常见品牌到分类的映射（瑞幸咖啡/蜜雪冰城 → 餐饮，滴滴/T3 → 交通，大参林 → 医疗，名创优品 → 购物），大幅压缩「其他」的占比。

三条都没命中时**留空并标记「没认出用途」，不编造、不阻塞记账**。App 首页会显示「22/24 笔已知用途」，你能直接看到自动化的真实覆盖比例，再决定要不要补那几笔。

**哪些情况注定要人工补**：只有金额、页面和通知里都没有任何商品字段的小额支付（微信零钱支付常见），以及商户名本身无法识别、品牌词典也查不到的情况。这类记录仍然自动入账、自动归类，只是用途空着。

**PWA 端跑同一套规则**：`parser.js` 实现了相同的字段抽取与品牌词典，桥接过来的记录不需要在手机上补过才能看到。

### 分类只有一份表

编辑弹窗的分类网格和自动识别以前各存了一份列表：解析器产出「居家 / 医疗 / 学习 / 其他」，网格里却是「住房 / 教育」，而且没有医疗和其他。结果很具体——一笔自动归成「医疗」的账，点开编辑，20 个格子**一个都不亮**，用户以为分类丢了，随手点一个最像的，原来的分类就被改名，同一类花销从此在统计里拆成两个桶。

现在 `LedgerCategories` 是唯一来源：网格只能从这张表来，解析器不允许输出表以外的名字，测试守着这条契约。历史数据里的旧名字（住房、教育）在启动时一次性归一到新名字，幂等、没有变化就不写盘。

「收入」也补进了收入网格——解析器对所有非退款收入只输出「收入」两个字，而网格里原先只有工资/兼职/报销……每一笔自动收入点开都是空选。

### CSV 导出与导入

备份文件（`.ziji`）是整份快照，只有这个 App 能读。要在电脑上做表、或者把手机端的记录搬到网页，需要能被别的软件打开的格式，所以补了 CSV：

- **导出**：手机端 8 列（`时间,收支,金额,商户,账户,分类,用途,原始通知`），网页端 7 列（`时间,方向,金额,商户,分类,账户,来源/备注`）。都带 UTF-8 BOM（否则中文版 Excel 会把中文读成乱码），以 `= + - @` 开头的字段加单引号防公式注入。
- **导入**：两端都能导。手机端在「设置 → 导入 CSV」，网页端在「自动化 → 本地数据 → 导入 CSV」。按**表头名**定位列，而不是固定下标——两份文件的列数和顺序都不一样，靠表头对齐才能互相导入；用户在 Excel 里插一列也不会整体错位。
- **时间格式统一**：两端都写 `2026-10-17 12:31:05`。网页端以前用 `toLocaleString("zh-CN")` 产出 `2026/10/17 12:31`，手机端的严格解析一条都认不出，用户看到的是「导入 0 条」。旧的斜杠格式仍然兼容，历史导出文件不用重做。
- **方向列是硬要求**：缺「收支 / 方向」列时整份文件拒绝导入。以前遇到这种文件会把每一行都当收入——金额分毫不差、方向全反，比导入失败难查得多。
- **账户不静默归并**：手机端的账户是自由文本（零钱、花呗、微信零钱），网页端只有几个内置账户。以前找不到就落到「其他」，金额没错但账户归属全丢，分账户余额直接失真。现在缺什么补什么，宁可多一个账户，也不改数据。
- **分类表两端一致**：22 个支出分类 + 收入 + 退款，一共 24 项，网页端与 `LedgerCategories` 逐项对齐，名称和顺序都相同。
- **去重**：`时间（秒）+ 金额 + 方向 + 商户`。恢复数据时多点一次导入，账本不会翻倍。
- **编码兜底**：先按 UTF-8 解，出现替换字符再按 GBK 解——中文版 Excel 另存默认是 GBK。
- **批量写盘**：一千条记录只写一次文件，而不是一千次 fsync。

往返无损、重复导入幂等、两端互相能导，都有测试守着（`LedgerCsvImporterTest`、`tests/csv.test.mjs`）。

网页端的导入链路还有一层**真浏览器**检查——单元测试看不到「按钮有没有接上 `change` 事件」「账户有没有被悄悄归并成其他」这类问题。先 `npm.cmd start`，再另开一个终端：

```powershell
npm.cmd run verify:pwa
```

它会以 430px 手机视口打开页面，切 tab、真实上传两份不同格式的 CSV、检查重复导入与拒绝逻辑，最后打印 `N/N 项通过`。需要本机有 Chrome 或 Edge，可用 `CHROME_PATH` 指定。

### 空备份不该清空账本

`importBackup("")` 以前返回成功，账本从有到无。触发路径很日常：点了「恢复备份」却没选文件、文件被网盘同步成 0 字节、或者读出来只剩一行表头。

现在只有「格式正确**且**有内容」的备份才会被接受。多报一次错，比多一次无声的数据丢失便宜得多。

### 金额不能「挑一个看起来像的」

支付通知里到处都是数字：`余额 1234.56`、`12:31`、`2026年`。以前金额识别是「取最像的那个」，于是余额、时间和年份都当过金额——一条「余额不足」的提示能记出 1234.56 元的支出。

现在每个候选金额都要过一道打分，且有最低采纳分：前面紧跟着时间冒号的（`12:31`）、被 `-/` 夹住的（日期）、没有货币符号也没有小数点且位数 ≥ 4 的（年份、卡号后四位），全部扣到线下。识别不出金额就不生成账单，交回手动记账——这正是「识别不到不要瞎记」的原则。

### 商户不是「标签后面的那串字」

支付结果页上「商品说明 / 摘要」后面跟的是商品名，`商户` 后面偶尔跟的是「商户单号」。以前这些标签都在商户候选里，一笔「生椰拿铁」能被记成商户「说明 生椰拿铁」，同一天的账还因此去不了重。

现在只认「商户 / 商家 / 收款方 / 付款方 / 交易对方」，并且用负向前瞻挡掉 `商户单号`、`付款方式`；「商品说明」整类标签不再参与。识别不到就写「未知商户」，等用户改一次，改完会按商户学一条规则。

### 跨月退款

9 月 28 日买 100、10 月 2 日退 100。若先按月切片再找原交易，10 月的列表里根本没有那笔支出，退款只能挂在 10 月，于是 10 月支出显示 −100，9 月还显示 100——两个月都错。

现在先用**全量账本**做归因（找到退款退的是哪一笔、属于哪个月、哪个分类），再按区间聚合。正确结果是 9 月净支出 0、10 月 0。趋势图也跟着改：退款扣在**原交易日**，而不是退款到账日，这样跨月不会在退款当月出现一根负柱。

## Android APK 构建

如果你还没有 Android SDK，可以让项目把 Android command-line tools 和构建 APK 所需包安装到当前目录的 `.android-sdk`：

```powershell
npm.cmd run android:setup-sdk -- -AcceptAndroidSdkLicense
```

这个命令会下载官方 Android command-line tools，并安装 `platform-tools`、`platforms;android-35` 和 `build-tools;35.0.0`。它需要你先确认接受 Google Android SDK License；如果你不想用项目内 SDK，也可以手动安装 Android Studio / Android SDK。

如果当前网络无法直接访问 `dl.google.com`，可以先用浏览器下载官方 command-line tools zip，然后让脚本使用本地文件：

```powershell
npm.cmd run android:setup-sdk -- -AcceptAndroidSdkLicense -CommandLineToolsZip C:\路径\commandlinetools-win-14742923_latest.zip
```

安装 Android Studio / Android SDK 后，或运行上面的项目内 SDK 安装脚本后，在项目根目录运行：

```powershell
npm.cmd run android:build
```

脚本会检查 Android SDK，调用 `android-companion\gradlew.bat assembleDebug`，成功后打印 debug APK 路径。当前电脑如果 `npm.cmd run doctor` 仍显示 `Android SDK - MISSING`，需要先安装 Android SDK 或运行 `npm.cmd run android:setup-sdk -- -AcceptAndroidSdkLicense`。

如果已经连接 Android 手机并开启 USB 调试，可以直接构建、安装并打开伴侣设置页：

```powershell
npm.cmd run android:deploy
```

安装后检查手机连接、App 安装状态和通知读取权限：

```powershell
npm.cmd run android:status
```

排查真机通知捕获时，可以查看伴侣日志：

```powershell
npm.cmd run android:logs -- -Follow
```

## 真机验证清单

只有完成下面这些步骤，才算“微信/支付宝/银行卡消费自动记账”在你的手机上真正跑通：

1. 运行 `npm.cmd run check:ready`，确认本地代码和桥接模拟通过。
2. 安装 Android Studio / Android SDK，或运行 `npm.cmd run android:setup-sdk -- -AcceptAndroidSdkLicense`，并让 `npm.cmd run doctor` 不再报告 `Android SDK - MISSING`。
3. 用 USB 连接 Android 手机，开启开发者选项和 USB 调试。
4. 运行 `npm.cmd run android:deploy`，把伴侣 APK 安装到手机。
5. 运行 `npm.cmd run start:lan`，让电脑启动局域网桥接服务，并记下脚本打印的 PWA 地址、`/api/capture` 地址和 token。
6. 在手机浏览器打开 PWA 地址，并用 `?bridgeToken=...` 地址保存 token。
7. 在伴侣 App 里填写 `/api/capture` 地址和 token，点击“检查桥接连接”或“发送测试账单”。
   如果你不小心把 PWA 的 `?bridgeToken=...` 链接粘进“桥接地址”，伴侣会自动转成 `/api/capture` 地址，并在 token 输入框为空时自动提取 token。
8. 运行 `npm.cmd run android:status`，确认伴侣已安装，并在系统设置里开启通知读取权限。
9. 运行 `npm.cmd run android:logs -- -Follow`，然后触发一笔真实微信、支付宝、银行卡或云闪付消费通知。
10. 在 Android 伴侣里查看这笔通知已自动入账；如果电脑桥接已配置，PWA 会同步同一笔记录，整个过程不需要逐笔确认。

如果某个 App 的通知格式暂时没被自动捕获，可以先打开支付详情或短信详情，把文本分享给 Android 的“发送到自记”入口；这会作为兜底方式进入待补发队列或直接发给桥接服务。

也可以把 `npm.cmd run start:lan` 打印的 `/api/capture` 地址、`?bridgeToken=...` 链接，或包含 `Bridge token: ...` 的整段文字发到手机后分享到“发送到自记”，伴侣会优先把它识别为桥接配置，而不是账单。
